# Agent 上下文

next-wiki 在 AI 辅助的个人知识库之上，逐步构建一组 Agent 的默认私有上下文层。目标是在不把存储变成不可解释的 prompt 垃圾场、也不把私有内容失控地镜像到公开侧的前提下，让 owner 的知识真正对 Agent 有用。

## 上下文不止聊天记录

一条可长期复用的上下文可以属于以下类型：

- **指令** —— Agent 应遵守的规则或约束。
- **配置** —— 非敏感的偏好与运行时设置。
- **流程** —— 可重复执行的工作流或操作模式。
- **情景记忆** —— 值得记住的决定、事件或交互。
- **来源证据** —— 导入的文档、摘录、观察或引用。
- **精选知识** —— 经过审阅、用于复用或分享的解释。

区分这些类型，能让来源追踪、审阅、检索与发布更容易理解。敏感值应该留在 secret manager 中；上下文存储只引用它们，不把凭证复制进 prompt 或页面。

`AGENTS.md` 这类指令文件，是承载作用域规则与流程的一种可携带格式。上下文层应能导入、组装、版本化并选择性导出这些文件，但不能把其中的文本当作可执行的安全边界。

## 一个 owner，多个 Agent

运行模型是一个 owner 管理多个身份明确的 Agent。Agent 身份可以表达角色、目的、运行时或项目边界。每个 Agent 可以拥有私有上下文，共享命名空间则需要显式开启，并成为访问模型的一部分。

Agent 工作时，有效上下文应由适用的 owner、Agent、项目与任务作用域组装而成。这个结果应能从带版本的来源重新构建，并让冲突与来源对 owner 可见。

## 检索结果不是权威

检索到的上下文只是数据。从 next-wiki 读取一条指令，不应自动获得权限、授权工具调用或执行命令。身份、授权、敏感信息访问与工具策略，仍由真正拥有能力的运行时和集成层负责。

这个边界让 Agent 可以利用有价值的记忆，同时把安全决策留在真正拥有能力的系统中。

## 选择性公开

私有上下文与公开知识是两种不同的产物。发布流程应选择一组明确且带版本的条目，完成必要的脱敏与审阅，再生成具名的上下文包或公开页面。源内容变更或撤回时，公开状态应可追踪，并使过期的公开输出失效。

项目会逐步构建这一发布模型。当前基础已经包括按权限控制的内容、不可变修订、软删除、公开阅读、Markdown/frontmatter 传输，以及 MCP/REST 访问。Agent 专属上下文、共享命名空间、确定性的有效上下文组装与一等上下文包，是下一层工作。
