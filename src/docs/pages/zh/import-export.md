管理员在 `/admin/transfers` 管理可移植备份与迁移。编辑者与读者无法访问迁移来源、任务、归档或报告。

## 可移植归档

站点导出会生成一个带版本的 ZIP，包含：

- `manifest.json`
- 带 YAML frontmatter 的已发布页面 Markdown
- 按内容寻址的被引用图片
- 一份导出报告

草稿、已删除页面、用户、权限、评论、修订历史与系统设置都会被**排除** —— 归档是可移植内容，不是数据库转储。

上传的归档会流式写入持久化内容卷，**在任何变更之前先校验**，并以 `skip` 或 `replace` 两种冲突处理方式进行预览。替换会追加一个新的已发布修订，并保留目标之前的修订，因此一次错误的导入总是可以回退。

产物默认保留 72 小时，可通过 `TRANSFER_*` [环境变量](/docs/environment)调整。

## 从 Wiki.js 迁移

从 Wiki.js 迁移是一等流程：

1. 创建一个 Wiki.js 来源：填写其 base URL 和一个有权列出页面、读取页面源码的 API token。凭据会被加密存储，API 永远不会回传。
2. Markdown 原样保留；CKEditor/HTML 页面会被转换为 Markdown 并标记为已转换。
3. 被引用的图片会被下载、校验、存入本地并改写为目标资产 URL。凭据只会发送给配置的 Wiki.js 源站。

私网目标默认被阻止；只对你确认过的 Wiki.js 主机开启私网信任。

## 恢复

- 任务与条目结果持久化在 PostgreSQL 中，浏览器刷新、产物过期都不会丢失。
- 进行中的任务可以协作式取消；失败/取消的任务可以发起重试，且不删除历史结果。
- 同一时间只有一个变更型导入能持有数据库变更槽。
- 任务详情页展示脱敏后的失败信息与归档下载；API 活动由 API 审计中间件记录。
